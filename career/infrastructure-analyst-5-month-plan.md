# Five-month Infrastructure Analyst job-switch plan

## Starting point and goal

- **Experience:** 2 years in AWS support.
- **Known services:** EC2, ACM, CloudWatch, and other AWS services.
- **Target:** Infrastructure Analyst roles in India.
- **Study time:** Up to 5 hours per week.

This plan builds on support experience. Prioritize troubleshooting, Linux, networking, AWS operations, automation, and communication over trying to learn every DevOps tool at once.

## Weekly routine

Aim for up to five hours:

- **2 hours:** learn one topic.
- **2 hours:** hands-on practice and notes.
- **1 hour:** resume, interview practice, or job applications.

If work or life is busy, keep the routine sustainable and resume the following week.

## Month 1 — Strengthen support fundamentals

- **Week 1:** Linux basics: files, permissions, processes, services, and logs.
- **Week 2:** Networking: DNS, HTTP/HTTPS, ports, routing, and security groups.
- **Week 3:** Practise with `curl`, `nslookup`, and Linux log commands. Write one small Bash or Python check, such as a disk-space or URL-health check.
- **Week 4:** Write up three real or practice incidents: symptoms, investigation, root cause, resolution, and prevention.

Do not include confidential customer or employer information in notes, interviews, or portfolio material.

## Month 2 — Build deeper AWS and Terraform skills

Review IAM, VPC, EC2, S3, CloudWatch, load balancers, backups, and cost awareness. Study the Terraform configuration in this repository. Practise `terraform fmt`, `init`, `validate`, and `plan`, and understand each resource before applying anything.

**Cost safety:** Terraform may create billable AWS resources. Check the plan and current pricing first. Reviewing configuration and plans is useful practice without deploying. If you do create resources, use a learning environment and clean them up afterward.

## Month 3 — Show practical automation

- Understand the GitHub Actions workflow and why tests run before deployment.
- Learn basic Docker concepts and run a small container locally.
- Improve the project README with how to test the project and troubleshoot it.
- Practise describing the project in two minutes: problem, design, security choices, testing, and improvements.

## Month 4 — Prepare your application

- Update your resume and LinkedIn using your actual AWS support experience: services handled, incident types, troubleshooting, escalation, documentation, and measurable outcomes you can verify.
- Practise explaining incidents using **situation → investigation → action → result**.
- Do one mock interview each week. Review Linux, networking, AWS, IAM, CloudWatch, and basic Terraform questions.
- Consider an AWS associate certification if it appears often in relevant job postings, but keep hands-on practice as the priority.

## Month 5 — Apply and interview

- Search for **Infrastructure Analyst**, **Cloud Operations Engineer**, **AWS Support Engineer L2**, and **Cloud Support Engineer** roles. Compare job descriptions because titles vary by company.
- Set a sustainable target, such as **4–6 well-matched applications and a few referral requests each week**.
- Track applications and follow up politely.
- Keep one technical practice session and one interview-practice session each week.
- Add questions you could not answer to a practice list and revisit them.

## Strengths to communicate

Your AWS support experience is relevant. Show that you can diagnose issues methodically, communicate clearly, automate repeatable work, and document safe resolutions. In interviews, use concrete examples and explain what you personally did.

You do not need to rush into Kubernetes for these roles. Build confidence in Linux, networking, AWS operations, and Terraform first.
